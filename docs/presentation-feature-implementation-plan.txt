================================================================================
UVALA AI PRESENTATION GENERATOR - IMPLEMENTATION PLAN
================================================================================

Project: Add AI-powered presentation generation to Coder Mode
Target Framework: Reveal.js (HTML-based presentations)
Model: Qwen3 Coder 30B (qwen.qwen3-coder-30b-a3b-v1:0)
Architecture: LLM → JSON → Renderer → HTML Preview

================================================================================
MAIN IDEA & PURPOSE
================================================================================

Enable users to generate professional, modern slide presentations from uploaded
content (PDFs, text files, case studies) directly within Coder Mode.

Key Value Propositions:
- Upload PDF → Get presentation in same chat (no context switching)
- Thread-scoped (tied to conversation/project context)
- Iterative refinement ("make slide 3 more visual" → regenerates)
- Multi-format export (HTML shareable, PDF printable)
- Privacy-first (all processing via Bedrock, no third-party SaaS)
- Modern visuals (charts, diagrams, stock images)

User Flow:
1. User uploads case study PDF to chat
2. User: "Create a 10-slide executive presentation from this"
3. AI analyzes PDF, generates structured JSON
4. System renders Reveal.js HTML presentation
5. Preview displays in chat (like flashcards do)
6. User can download HTML or export to PDF

ARCHITECTURE OVERVIEW
================================================================================

High-Level Flow:
┌─────────────┐     ┌──────────────┐     ┌─────────────┐     ┌──────────────┐
│ User Upload │ --> │ Extract Text │ --> │ LLM JSON    │ --> │ Render HTML  │
│ PDF/Text    │     │ (existing)   │     │ Generation  │     │ (Reveal.js)  │
└─────────────┘     └──────────────┘     └─────────────┘     └──────────────┘
                                                │
                                                v
                                         ┌──────────────┐
                                         │ Display in   │
                                         │ Chat Preview │
                                         └──────────────┘

Technical Pattern:
1. Input: PDF/Text file + user requirements ("10 slides, executive audience")
2. Extraction: Use existing processDocument() to get text
3. LLM Call: Qwen Coder generates structured JSON (NOT raw HTML)
4. Rendering: Convert JSON → Reveal.js HTML template
5. Display: Show in chat using ```html code block (proven with flashcards)
6. Export: Provide download buttons for HTML/PDF

Why JSON Output (not direct HTML):
- LLM focuses on content, not formatting
- Deterministic rendering (consistent styling)
- Easy to validate and debug
- Separation of concerns (content vs presentation)
- Can reuse same JSON for different themes

JSON Schema Example:
{
  "title": "Presentation Title",
  "theme": "white",
  "slides": [
    {
      "type": "content",
      "title": "Slide Title",
      "content": ["Bullet 1", "Bullet 2"],
      "notes": "Speaker notes",
      "chart": { "type": "bar", "data": {...} },
      "mermaid": "graph TD\n  A-->B"
    }
  ]
}

================================================================================
PRESENTATION SYSTEM PROMPT (CORE LOGIC)
================================================================================

Key Instructions for LLM:
1. Output ONLY valid JSON, no explanations or markdown
2. Structure: { title, subtitle, theme, slides[] }
3. Each slide: { type, title, content[], notes, chart?, mermaid? }
4. Slide types: title, content, two-column, quote, image, blank
5. Content: 3-5 bullets per slide, concise (1-2 lines each)
6. Visuals: Use mermaid for processes, chart.js for data
7. Total slides: 5-10 (depending on content depth)
8. Professional tone, minimal text (support speech, don't replace)

Example JSON Output:

REVEAL.JS RENDERER TEMPLATE
================================================================================

Basic Template Structure:

function renderRevealPresentation(presentationData) {
  return `<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <title>${presentationData.title}</title>
  <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/reveal.js@5/dist/reveal.css">
  <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/reveal.js@5/dist/theme/${presentationData.theme}.css">
  <script src="https://cdn.jsdelivr.net/npm/mermaid@10/dist/mermaid.min.js"></script>
  <script src="https://cdn.jsdelivr.net/npm/chart.js@4/dist/chart.umd.js"></script>
  <style>
    .reveal .slides { text-align: left; }
    .reveal ul { margin-left: 1em; }
    .reveal h2 { margin-bottom: 0.5em; }
  </style>
</head>
<body>
  <div class="reveal">
    <div class="slides">
      ${presentationData.slides.map((slide, index) => renderSlide(slide, index)).join('')}
    </div>
  </div>
  <script src="https://cdn.jsdelivr.net/npm/reveal.js@5/dist/reveal.js"></script>
  <script>
    Reveal.initialize({
      hash: true,
      transition: 'slide',
      backgroundTransition: 'fade'
    });
    mermaid.initialize({ startOnLoad: true });
  </script>
</body>
</html>`;
}

function renderSlide(slide, index) {
  if (slide.type === 'title') {
    return `
      <section>
        <h1>${slide.title}</h1>
        ${slide.content ? `<h3>${slide.content.join('<br>')}</h3>` : ''}
      </section>
    `;
  }

  if (slide.type === 'content') {
    return `
      <section>
        <h2>${slide.title}</h2>
        <ul>
          ${slide.content.map(item => `<li>${item}</li>`).join('')}
        </ul>
        ${slide.mermaid ? `<div class="mermaid">${slide.mermaid}</div>` : ''}
        ${slide.chart ? `
          <canvas id="chart-${index}" width="400" height="300"></canvas>
          <script>
            new Chart(document.getElementById('chart-${index}'), {
              type: '${slide.chart.type}',
              data: ${JSON.stringify(slide.chart.data)}
            });
          </script>
        ` : ''}
      </section>
    `;
  }

  return '<section><p>Unsupported slide type</p></section>';
}

================================================================================
POTENTIAL CHALLENGES & MITIGATIONS
================================================================================

Challenge 1: LLM generates invalid JSON
Mitigation:
- Use JSON mode / structured output if available
- Add JSON validation with zod schema
- Retry with error feedback
- Fallback to template if parsing fails

Challenge 2: Large PDFs exceed token limits
Mitigation:
- Chunk document, generate outline first
- Let user approve outline before full generation
- Generate slides in batches
- Summarize each chunk before slide generation

Challenge 3: Inconsistent styling
Mitigation:
- Don't let LLM control CSS
- Use fixed Reveal.js themes
- JSON controls content only, not presentation
- Deterministic renderer ensures consistency

Challenge 4: Image licensing issues
Mitigation:
- Use only free stock APIs (Pexels, Unsplash)
- Include proper attribution
- Clearly mark images as placeholders
- Let user upload custom images

Challenge 5: PDF export quality
Mitigation:
- Use proven tools (DeckTape, Puppeteer)
- Pre-render all slides before PDF generation
- Set proper print CSS
- Test with multiple browsers

Challenge 6: Slow generation for complex presentations
Mitigation:
- Stream JSON generation (show progress)
- Render slides incrementally
- Cache common templates
- Optimize LLM prompt for speed
